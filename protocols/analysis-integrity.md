# AMBER 分析诚信协议（analysis-integrity）v0.1

状态：正式 · 2026-09-21 · 触发：指标数量增长后的防错机制（owner 问「这么多指标怎么保证分析不出错」）

目的：指标可以错，机制不允许错得没人知道。可信度不靠「从不出错」，靠「出错必认、认得比谁都快」。

## 1. 事实层与判断层分离

- **事实层**：机器可读的硬事实——超时、退出码、验证结果、token、墙钟。只允许纯规则提取（正则/结构化字段），禁止 LLM 参与。
- **判断层**：归因、解读、结论。允许错、允许被推翻；推翻时只改判断，不动事实。
- 两层分开存放。判断层每一条必须标注来源（哪个事实、哪个文件、什么时间戳）。

## 2. 发布数字必须可复算

- 任何进入公开页面/报告的数字，必须能从原始数据（transcript / manifest / 成绩 md）用脚本一键重算。
- 手写数字禁止进入公开材料。
- 每个公开数字的溯源链 = 生成脚本路径 + 该脚本的 commit hash。
- 复算失败 = 撤回该数字，不是改脚本凑数。

## 3. 抽验门禁

- 公开发布前，由编排方（Vesper）亲手抽验至少 1 条/类。
- 抽验标准不是「看着合理」，是**回原始记录逐条核对**（开 transcript、看 exit code、看验证输出）。
- 抽验不通过 = 整批不发布，不是把抽到的那条改掉。

## 4. 换脑复核

- 生产数字的脑与核验数字的脑必须不同（谁生产谁不许验收）。
- 重大对外结论（新指标上线、口径变更、涉及厂商信誉的发现）走红道盲审。

## 5. 错了就改、留痕

- 发现已发布数字错误：公开更正，写进 `docs/corrections-*.md`（先例：corrections-2026-09-18.md）。
- 更正内容 = 错什么 + 正确值 + 错因 + 影响了哪些结论。
- 不删除错误版本，保留历史可查。

## 6. 标签纪律

- 信号不够一律标 `unknown`，禁止硬塞标签制造假确定性。
- 同一对象允许多标签并存，禁止单标签强归类。
- 内部案号不出现在任何公开文件；公开只用别名（A-xxxxxxxx）。
