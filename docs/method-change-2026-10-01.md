# 方法变更 2026-10-01：hermes 道的系统提示只保留净室内容

> Method change. English version: [method-change-2026-10-01.en.md](method-change-2026-10-01.en.md)

## 变了什么

AMBER 用 [Hermes](https://github.com/NousResearch/hermes-agent) 作答的车道（下称 hermes 道），以前开着工具的考卷会话里，系统提示除了公开的净室 SOUL 和 Hermes 自带的工具、环境说明，还多出两段由 Hermes 自动加入的内容：

1. 一段角色说明，大意是「你是在用户代码库里结对的 coding agent」；
2. 一段工作区快照，内容是考卷目录所在 git 仓的根路径、分支，以及这个仓最近 3 条提交的标题。

**原因**：Hermes 自 2026-06-10 起（上游 #43316）会判断会话是不是「coding 场景」。判断方法是在运行它的机器上，从会话的工作目录往上找 git 仓。AMBER 的考卷目录放在考场的 git 仓里面，所以开着工具的会话都被判成了 coding 场景。

快照里没有题面、判分程序或答案，提交标题是考场仓的维护记录。但这两段不属于我们公开承诺的净室条件，所以关掉。

## 从哪一场起

考场版本 2026-10-01 起，也就是 amber-run `65bea1bc` 之后开考的场次：

- 每份考卷的 Hermes 配置都设 `agent.coding_context: off`；
- 考卷目录移到任何 git 仓之外，开考前自动检查，不满足就不开考；
- 期文的 Run identity 会标出考场版本。

从这一场起，系统提示只有净室 SOUL，加上 Hermes 自带的工具和环境说明，后者与以往相同。

## 对已发布成绩的影响

- **2026-W40 及以前的 hermes 道成绩**：都在带这两段的条件下考出，彼此条件一致，照旧有效，不改分。这一行为早于 AMBER 第一期；但各期 2651 考场用的是哪个 Hermes 版本，我们没有逐期核对，这句结论以我们核对过的版本为准。
- **不经 Hermes 作答的车道**（Devin、WorkBuddy ACP 直连）：不受影响。
- **跨期比较**：拿这个日期前后的 hermes 道成绩作比较时，请把这次变化当作一次考场条件变化。
